2. UNITS ISSUE (pixel scale)
--------------------------------------------------------------------------------
One variable name `pixel` is overloaded for two different physical quantities:

  (a) SCREEN / GRID sampling  -> METERS  (spacing of the atmospheric screen;
      sets size = 2*ngrid*pixel and Fresnel propagation). Value: 0.017664 m.
      This usage is CORRECT in simatm and in most of ringsim
      (size, nblur, jstep, radpix = d*0.5/pixel*ksamp). LEAVE IN METERS.

  (b) DETECTOR PLATE SCALE -> ARCSEC / CCD PIXEL. This is what the ring geometry
      and ALL of getweight5 / aweight / profrest5 mean by "pixel".
      In aweight.py: ringrad = ringradpix2 * asperpix / pixel  =>  pixel = arcsec/px.
      La Serena par confirms: "pixel":1.58  (1.58"/px).

The notebook ALREADY holds the correct arcsec scale in `pixscale`:
      pixscale = pixsize/effl*206265 = 6.9e-6/1.20845*206265 ≈ 1.178 "/px
and already uses it correctly for oversampling (d1 = wavelen/pixscale*206265).

THE BUG: in the ringsim cell, `asperpix` is wrongly set to the meters value
(asperpix = pixel) instead of the grid-derived arcsec value. Everything that
depends on asperpix (ring radius in CCD pixels, the discrepancy check) is
therefore wrong/meaningless.

REQUIRED EDITS (small, self-contained; DO NOT globally rename `pixel`):

  [sim1.par cell] Fix comment only:
      pixel = 0.017664   # atmospheric screen sampling, METERS (not arcsec)

  [ringsim cell] Replace the wrong asperpix with the grid-derived scale
  (this is the line currently commented out):
      asperpix = 206265 * wavelen / (nap * pixel / ksamp) * npixperpix  # arcsec/CCD px

  [ringsim cell] Fix the discrepancy check (currently compares arcsec vs meters,
  so it can never fire). Compare grid scale to the nominal detector scale:
      if abs(asperpix / pixscale - 1.0) > 0.05:
          print(f'Discrepant pixel scale! grid={asperpix:.4f}" vs detector={pixscale:.4f}"')
          print(f'Re-run SIMATM with screen pixel = {pixel * asperpix / pixscale:.6e} m')
          raise ValueError('Pixel scale discrepancy exceeds 5%. Aborting.')

  [writefits cell] PIXSCALE is written as meters but labeled arcsec. Use:
      header['PIXSCALE'] = (float(asperpix), 'Arcseconds per CCD pixel')

  [future par dict for getweight5/profrest5]:
      par["telescope"]["pixel"]      = float(pixscale)     # arcsec/px (~asperpix after fix)
      par["telescope"]["ringradpix"] = float(rradiuspix)   # ring radius in CCD pixels
